# بازبینی معماری و مهاجرت به v2 — ۲۰۲۶/۰۸/۱۲

> **محدودیت محیط**: در این sandbox دسترسی به `dotnet`/docker مسدود است؛ بنابراین
> build اجرا نشد. این بازبینی بر پایهٔ بررسی ایستا و بازسازی ساختار انجام شده است.
> قبل از استقرار، `dotnet build` و تست دستی با SQL واقعی لازم است.

## خلاصه

معماری v1.5 (۱۱ پروژه: ۷ کلاینت WASM + webapi + share + blazordeployservice +
tests) به درخواست مالک محصول با معماری v2 جایگزین شد:

**یک پروژهٔ Blazor Server (`Tarazin`) + MudBlazor + اسکریپت‌های TSQL نامدار که
در همان پروسه با Dapper اجرا می‌شوند.**

## چه چیزهایی حذف شد

| آیتم | علت |
|---|---|
| `webapi/` (کنترلرها، session، handshake، outbox processor، backup) | دیگر لایهٔ HTTP لازم نیست |
| `accounting/…store/`, `central-client/` (۷ کلاینت WASM) | ماژول شدند داخل `Modules/` |
| `share/` | مدل‌ها به `Models/` منتقل شدند |
| `blazordeployservice/` (پکیج NuGet + Bootstrap) | MudBlazor جایگزین شد |
| `tests/Tarazin.ContractTests` | تست‌های مرتبط با webapi؛ با build + اسکن جایگزین شد |
| توکن/رمزنگاری AES/هندشیک/URL-token | نشست درون‌پروسه‌ای `UserSession` |
| بک‌بون رویدادها (Outbox فعال) | ADR-002 — رویدادها خواب‌اند؛ عملیات مستقیم و تراکنشی |
| جداول `Projects`/`Sessions` در webapi | دیگر وجود ندارند |

## چه چیزهایی حفظ شد

- **۹۹ اسکریپت TSQL** (report-first) → `Tarazin.Data/Scripts/{schema}/`
- **اسکیمهٔ مستقل هر محصول** و قفل مرز اسکیمه (اسکن `tools/cross-schema-scan.sh`)
- **قراردادهای ۸‌گانه** → `Models/SharedModels.cs` (ADR-003)
- **ممیزی tenant-aware** → `AuditService` → `[central].[AuditLog]` (یکپارچگی زنجیرهٔ هش هنوز نیازمند اصلاح و تست پویا است)
- **گزارش‌محوری** و ساختار چهاربخشی هر ماژول (Entry/Special/Reports/Settings)
- **متن‌های فارسی/RTL** و فرهنگ تاریخ شمسی

## ریسک‌های باقی‌مانده (v2)

1. **بدون build تأییدشده در sandbox** — اولین کار بعد از دسترسی به محیط:
   `dotnet restore && dotnet build Tarazin.slnx`.
2. **نسخهٔ MudBlazor** (9.8.0) با net8.0 ساخته می‌شود (.targets شامل net8.0 است) — در CI تأیید شود.
3. **Outbox ها** در DDL باقی‌اند ولی استفاده نمی‌شوند — پاک‌سازی اختیاری.
4. **اعتبارنامهٔ SQL و bootstrap password** فقط از secret store سمت Web تزریق شوند؛ فایل‌های tracked فاقد مقدار secret هستند و هیچ password پیش‌فرضی وجود ندارد.
5. **مسیر MAUI** — broker/RLS و artifactهای هر target باید پیش از release با SQL واقعی، تست adversarial و decompile/string scan تأیید شوند.
