## ۱. وضعیت فعلی پروژه (خلاصهٔ بازبینی)

معماری فعلی مطابق `skills/blazor/tarazin-project-architecture` و
`.agents/tarazin-tsql` است: پنج پروژه با وابستگی یک‌طرفه
(`Share ← Data ← Ui ← {Web, Maui}`)، دسترسی به داده با **Dapper + اسکریپت‌های
TSQL نامدارِ Embedded** (بدون HTTP)، UI با **MudBlazor**، احراز هویت با
**PBKDF2**، و ممیزی **ضدّ دستکاری با زنجیرهٔ هش**.

ماژول‌های موجود (۷ اسکیمه): `central`، `accounting`، `inventory`، `treasury`،
`payroll`، `goldshop`، `store`. هر ماژول ۶ صفحه دارد (خانه/داشبورد/ورود عملیات/
عملیات ویژه/گزارشات/امکانات).

## ۳. آنچه در این تغییر اضافه شد

مطابق درخواست، چهار کار زیر روی همین معماری (بدون افزودن پروژهٔ جدید) انجام شد:

### ۳.۱ کنترل دسترسی (RBAC) برای هر بخش
- **کاتالوگ دسترسی**: `Tarazin.Share/Permissions.cs` — ۴۶ دسترسی با الگوی
  `{module}.{action}` (view/entry/special/reports/settings/admin برای ۷ ماژول +
  ۴ دسترسی سیستمی `system.users/roles/audit/admin`).
- **نقش‌های پیش‌فرض**: مدیر سیستم، حسابدار، صندوق‌دار، انباردار، فروشنده،
  کارگزینی، حسابرس، فقط مشاهده.
- **دیتابیس**: جداول `[central].[Permissions]`، `[central].[Roles]`،
  `[central].[RolePermissions]` + ستون `Users.RoleId` (با FK و Migration
  idempotent) + اسکریپت‌های `PermissionSync/RoleSync/RolePermissionSync/
  UserRoleBackfill` که در استارت‌آپ از کاتالوگ C# همگام می‌شوند.
- **نشست**: `UserSession.HasPermission/CanView/HasAny` + بارگذاری دسترسی‌ها
  هنگام ورود.
- **اعمال در UI**: فیلتر منو و کارت‌های خانه بر اساس دسترسی، گارد مرکزی مسیر
  در `MainLayout` (نمایش «دسترسی ندارید»/«ابتدا وارد شوید»)، صفحهٔ جدید
  «نقش‌ها و دسترسی‌ها» (`/central/roles`) با ویرایشگر چک‌باکسی گروه‌بندی‌شده.

### ۳.۲ سرویس کاربر (UserService)
- `Tarazin.Ui/Services/UserService.cs`: ایجاد/ویرایش/حذف کاربر، دریافت کاربر،
  دریافت دسترسی‌های کاربر، مدیریت نقش‌ها و دسترسی‌ها (هش رمز PBKDF2 در خود سرویس).
- صفحهٔ `/central/users` و دیالوگ ویرایش کاربر (با انتخابگر نقش) از این سرویس
  استفاده می‌کنند.

### ۳.۳ CreatedAt / UpdatedAt برای همهٔ بخش‌ها
- **همهٔ جداول موجودیت** (`_Ensure.sql` هر اسکیمه) ستون‌های
  `CreatedAt/UpdatedAt/CreatedBy/UpdatedBy` را (با Migration idempotent) دارند.
- **اسکریپت‌های Upsert** هنگام ویرایش `UpdatedAt` (و در جداول مرکزی `UpdatedBy`)
  را ثبت می‌کنند؛ **اسکریپت‌های List/Search** آن‌ها را برمی‌گردانند؛
  **مدل‌های `Tarazin.Share`** همه `CreatedAt/UpdatedAt` دارند.
- استثناهای عمدی: جداول زیرساختی/پیوست‌نما (`Outbox`، `Sessions`، `AuditLog`،
  `*Snapshot`، `CartItems`) که پیوست‌فقط هستند یا معنای ممیزی خودشان را دارند.

## ۴. چرا بخش‌های «ندار» را یک‌جا نساختم

لیست ۳۳‌بندی عملاً یک ERP کامل است. در این تغییر، تمرکز روی چهار خواستهٔ صریح
شما (دسترسی برای هر بخش + سرویس کاربر + CreatedAt/UpdatedAt) و زیرساختِ لازمِ
آن‌ها بود. مابقی بخش‌ها (اموال، اقساط، POS، BI، اعلان‌ها، …) به‌عنوان Backlog
در `todo.md` ثبت می‌شوند و هرکدام با همان الگو (گزارش‌محور → مدل → اسکریپت →
صفحه) قابل افزودن‌اند.
